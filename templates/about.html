Academic Project Title & Problem Statement

Capstone / Internship Project

Community Health Data Collection & Analysis

Problem Statement:

Community health insights are severely constrained because health-related data is fragmented, manual, difficult to collect, and challenging to analyze in real time. Healthcare planning and resource allocation become unreliable when community-level epidemiology is unavailable or scattered across disparate, non-standardized sources.

Project Objective:

Build a user-friendly, full-stack web application that empowers healthcare workers, public health officials, and community coordinators to collect, standardize, manage, analyze, visualize, and understand community health data to drive proactive healthcare planning.

System Architecture & Data Flow

Full-Stack Implementation
1. Frontend Presentation Layer
  • HTML5 & CSS3: Custom responsive design system with medical color themes and print stylesheets.
  • Vanilla JavaScript (ES6+): Real-time BMI calculation, dynamic multi-attribute filtering, debounce search.
  • Chart.js: Interactive canvas-rendered epidemiology graphs (Doughnut, Bar, Polar Area, Line).
2. Application Backend (Python Flask)
  • Flask 3.x Engine: Lightweight WSGI application handling routing, Jinja2 template rendering, and REST APIs.
  • Clinical Validation Engine: Server-side bounds checking for vitals, height, weight, and blood pressure.
  • Export Controller: Dynamic CSV and formatted JSON streaming generators.
3. Persistence Layer (SQLite3)
  • SQLite Database: Embedded, zero-configuration relational database engine (community_health.db).
  • B-Tree Indexes: Fast lookup indexes on location, gender, diabetes, and risk score columns.
  • Seed Generator: Realistic, statistically correlated baseline data generation for instant evaluation.

Data Ethics, Anonymization & Privacy Compliance

Safe Synthetic Dataset

In accordance with public health informatics ethics and regulations (including HIPAA Safe Harbor De-identification and GDPR principles):

Zero Personally Identifiable Information (PII) No names, phone numbers, social IDs, street addresses, or dates of birth are collected or stored.
Synthetic Sample Population All records are synthetically generated based on real-world epidemiology distributions for academic demonstration.
Anonymized Sequential Identifiers Records are identified solely through sequential codes (e.g., CHD-1042) ensuring complete participant privacy.

College Project Review / Viva Q&A Guide

Presentation Helper

Q1: Why did you choose Python Flask and SQLite for this project?

Answer: Flask is a microframework that provides high transparency, clean routing, and minimal overhead, making it ideal for academic demonstration. SQLite provides a self-contained, serverless zero-configuration relational database that requires no external database service setup while fully supporting standard SQL queries, indexes, and transactions.

Q2: How are clinical indicators (BMI, BP category, Risk tier) determined?

Answer: They are classified using standard global medical guidelines: WHO classification for Body Mass Index (Underweight <18.5, Normal 18.5-24.9, Overweight 25-29.9, Obese ≥30), American Heart Association (AHA) guidelines for Blood Pressure (Normal, Elevated, Stage 1, Stage 2, Crisis), and ADA fasting criteria for blood glucose. The overall risk tier is calculated using a weighted comorbidity scoring matrix.

Q3: How does this system solve the fragmentation problem stated in the objective?

Answer: It provides a centralized digital ingestion portal with immediate validation, automatic metric derivation, and real-time dashboard aggregation. Healthcare administrators can immediately view geographic disease burden, filter by age/gender, and export data or print executive assessment reports with a single click.

Q4: What future enhancements could be added to this project?

Answer: Future extensions could include GIS interactive mapping (Leaflet.js) to display disease clusters geographically, machine learning models (e.g., Logistic Regression or Random Forests) to predict individual 5-year chronic disease risk, and multi-user role-based authentication (Field Surveyor, Clinician, Health Director).
